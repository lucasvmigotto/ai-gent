# Engine matrix: Rust drivers for the dbrun spike (T002)

One row per engine for the driver survey of `specs/038-db-runner-spike/tasks.md` task T002, feeding E2-E6 and the verdict in `specs/038-db-runner-spike/decision.md`. The rows start from the research table and the engine x route table of `docs/product/dbrun-spike-report.md` and re-state each candidate across the fields T002 lists: crate, version, maintainer activity, native library needs, TLS, timeouts, statement-limit support, result-type mapping to the runner's JSON, effort in tasks, verdict-relevant risks.

Claims are labelled per `shared/research.md`. A claim sourced in this run carries `[RESEARCHED: S<n>]` and a row in the Sources table below (columns `#`, claim, URL, retrieved date ISO, confidence, label). `[KNOWN]` marks stable knowledge on non-obvious claims only; every other claim — the report's assumptions, wrapper-crate inferences and unverified starting points — is `[ASSUMPTION]`.

## Fallback route (not an engine row)

The matrix has the six engines the spec lists. The process fallback is a route, not an engine: no Rust crate, the process connector spawns `dbrun.py _exec` with JSON on stdin and one JSON line back (T013) [RESEARCHED: S9] — docs/product/dbrun-spike-report.md. It needs no native library of its own and runs the pinned Python driver in a child process [RESEARCHED: S9]. Its TLS defaults and timeout enforcement through the helper were not exercised [ASSUMPTION]. Today `db` requires `uv` or a container engine, and a plain install cannot run it, as `specs/038-db-runner-spike/spec.md` states [RESEARCHED: S9].

## Closed unverified items

### The `mysql` repository 404

The report read the `mysql` repository page, got a 404 and therefore treated the crate's TLS options as assumed. Re-checked this run: crates.io indexes `mysql` 28.0.4 at https://github.com/blackbeam/rust-mysql-simple and `mysql_async` 0.37.1 at https://github.com/blackbeam/mysql_async, both of which exist today, and the stale path https://github.com/grayblake/rust-mysql answers 404 now [RESEARCHED: S5, S6].

The two crates' TLS options are now split per source: `mysql` 28.0.4 declares the TLS features `native-tls`, `rustls`, `rustls-tls` and `rustls-tls-ring` [RESEARCHED: S5] — https://crates.io/crates/mysql/28.0.4; `mysql_async` 0.37.1 declares rustls through the `rustls-tls` feature with the `aws-lc-rs` provider, its own source being the crates.io feature list and the repository README [RESEARCHED: S5] — https://crates.io/crates/mysql_async/0.37.1, https://github.com/blackbeam/mysql_async.

Closed: the repository 404 was a stale path, and TLS is an explicit crate feature, not an assumption [RESEARCHED: S5, S6].

### rustls for tokio-postgres

The report carried rustls for `tokio-postgres` as a third-party search snippet only. Re-checked this run: the docs.rs page for `tokio-postgres` 0.7.18 states that TLS support is implemented through external libraries, with `NoTls`, `postgres-native-tls` and `postgres-openssl`; the crate's own feature set contains no rustls feature; the third-party crate `tokio-postgres-rustls` 0.14.0 supplies rustls with the `aws-lc-rs`, `ring`, `webpki-roots` and `native-certs` features [RESEARCHED: S2, S3].

Closed: rustls is available for `tokio-postgres` through the third-party `tokio-postgres-rustls` crate, not bundled upstream [RESEARCHED: S2, S3] — https://crates.io/crates/tokio-postgres-rustls/0.14.0.

### The RustSec claim on `tiberius` (narrowed, not closed)

The report recorded, with doubt, that a fork author called `tiberius` effectively unmaintained and raised open RustSec TLS advisories. Re-checked this run: the RustSec advisory database holds an advisory for `tiberius`, RUSTSEC-2020-0010, dated 2020-02-28, marked informational and unmaintained, with no patched version and unaffected versions above 0.3.2, and the advisory text says the author archived the repository and did not intend to maintain the 0.3 version relying on the old futures ecosystem [RESEARCHED: S7].

Narrowed (corrected by the supervisor), not closed: the 2020 notice does not by itself show the current line unmaintained, and this run's sources show only that the `tiberius` repository is not archived and was last pushed on 2026-09-25 (https://github.com/prisma/tiberius); the RustSec advisory RUSTSEC-2020-0010 covers 0.3.x only and lists versions above 0.3.2 as unaffected; ongoing maintenance and whether any other advisories exist were not established. The fork `tiberius-ng` 0.13.1 (pushed 2026-10-03) remains the candidate the spike measured with rustls; whether the upstream 0.13 line offers rustls too is still to be confirmed [RESEARCHED: S7].
