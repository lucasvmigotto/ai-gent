# Experiments (each rule is fixed before it runs)

All prototypes live in `rust/spikes/dbrun/` and use only throwaway containers (images and memory caps as in `scripts/test-dbrun-engines.py`) or a temp sqlite file. Fixture password: the engines script's throwaway value only.

| # | Question | Method | Pass | Fail |
|---|---|---|---|---|
| E1 | Does the safety core port with no behaviour change? | Generate a `golden.json` by running the real Python (171 strings over 6 engines: classify verdicts with reason text, splits, `is_ddl`, cost cases, mask with reveal on and off, redact, network), commit the generator, and use the file as fixtures. Port `scan`, `split_statements`, `classify_statement`, `is_ddl`, `catalog_only`, `cost_rules`, `mask_*`, `luhn`, `redact`, `network_args`, `parse_modes` to a driver-free library; turn the cases of `ClassifierTest` (8), `CostTest` (2), `MaskTest` (3), `RedactTest` (2), `NetworkTest` (1) into fixtures | all fixture cases identical on both implementations, reason text included; the lookaround gaps (Oracle `DBMS_` exclusion, redaction boundaries) are recorded. Seed: the report measured zero diffs on 1026 verdicts and 4104 cost cases, reads only | any difference not explained by a Python bug (then the bug is recorded and fixed first) |
| E2 | PostgreSQL native | prototype with a Rust PostgreSQL client against `postgres:17`: connect, session options (`statement_timeout`, `lock_timeout`, `idle_in_transaction_session_timeout`, read-only), run the engines script checks through a thin adapter | all engine checks incl. a write refused by the server in read mode (`transaction_read_only=on`); errors read through `as_db_error()`; TLS option chosen and noted (native-tls, openssl or `tokio-postgres-rustls`). Seed: read and server refusal shown on 17 with NoTls | any check fails or needs a native library |
| E3 | MySQL and MariaDB native | same with `mysql:8.4` and `mariadb:11.4`; per-session timeout variable chosen after `SELECT VERSION()` | all checks on both, a write refused by the server (ERROR 1792 shown); TLS noted. Seed: one `mysql` crate binary served both | a timeout cannot be enforced, or MariaDB and MySQL need different clients |
| E4 | SQLite native | `rusqlite` or equivalent with a bundled build; the `SqliteEndToEndTest` cases | 8 cases pass; no system libsqlite needed | needs a system library |
| E5 | SQL Server | candidate `tiberius-ng` 0.13.1 (rustls) versus the original `tiberius` 0.13.0: a fork-health check (maintainers, last release, open RustSec advisories, whether the original is really unmaintained); prototype against `mssql/server:2022-latest` (the test image needs `trust_cert`, never a default); also `sqlcmd` in a client image as the fallback. SQL Server has no server-side read-only mode: the decision states that the classifier and a rollback are the only barrier | one route passes all checks incl. TLS to the 2022 image and the fork-health check is recorded. Seed: read over TLS worked, 69 ms | none passes: container route only |
| E6a | Oracle, `oracle` crate 0.6.3 (ODPI-C) | against `gvenzl/oracle-free:23-slim` with Instant Client in a throwaway container | a route passes all checks without shipping Oracle client libraries (expected to fail) | needs Instant Client on the user's machine: not shippable, container or helper route only |
| E6b | Oracle, `oracledb` 26.0.0-beta.5 (pure Rust, thin) | same image; include the DPY-3015 / 10G password-verifier case and TLS | passes all checks incl. the legacy verifier and TLS | beta, a check fails or is untestable: the Python helper stays (option H-exec) |
| E7 | Windows | run E1 and E4 on a Windows runner; the client-container network namespace join on Docker Desktop or a Podman machine | E1, E4 pass; the join works or is documented unsupported | E1 or E4 fail |
| E8 | Size and build cost | release binary size and build time with each driver set (N, H, H-exec, C) on Linux x86_64 and aarch64, plus the toolchain needs: aws-lc-rs versus ring, a C compiler for bundled sqlite, musl, aarch64, Windows. Seed (x86_64 gnu, z, LTO, strip): core 1.56 MB, + sqlite 2.63, + postgresql 2.09, + mysql 1.98, + mssql 3.72, sqlite + postgresql + mysql 3.52, all about 5-6 (estimate) | numbers recorded; H or N within a size budget the owner sets (starting figure: +10 MB over the no-db binary, arbitrary, the owner may change it) | not measured |

Cold start is recorded beside size, against the Python baseline (stdlib start 24 ms; warm `uv run --with PyMySQL` 176 ms before connecting). Experiments not run so far: Oracle; plan, apply and restore; the remote-declared checks; PostgreSQL and MySQL TLS; musl; aarch64; Windows.

Results go in `specs/038-db-runner-spike/results.md` (one section per experiment: date, machine, commands, outcome), then are summarised in `decision.md`.
