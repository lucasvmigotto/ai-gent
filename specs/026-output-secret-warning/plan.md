# Implementation Plan: Secret warning and redaction for tool output

**Branch**: `docs/mod-specs-2` (spec) | **Date**: 2026-10-31 | **Spec**: `spec.md` | **Research**: `research.md`

## Summary

The `secrets` plugin's hooks module hooks `session.append` with `{ door: 'tool-result' }` (with a `.catch` that replays `next(e)`), scans the row's text with 016's `compile` (the high-confidence kinds), and — for a row whose `e.origin.tool` is in the redact list (default `Bash`, `WebFetch`) — passes `next` a message with each match replaced by `<kind>`; every other row is passed on unchanged. A toast names kind, count and tool with rotate-and-store advice. No match is ever kept.

## Technical Context

**Language**: TypeScript hooks module. **Engine**: Claude Code 2.1.312 (the CI pin; the event, the `door` matcher and `$.session.usage` passed `claude plugin validate` on it on 2026-10-31; the rewrite and the origin shape were read from the 2.1.316 types and are confirmed by task 1). **Events**: `session.append` (door `tool-result`). **Storage**: `$.state` for the toast-rate counters only. **Project Type**: Claude Code plugin module.

## Implementation order (tests first)

1. **Probe on the pin (R1)**: a `claude plugin test` case that raises a `tool-result` row and asserts `origin.tool` and the `content` shape and that a rewritten row is what `next` stores; record the result in `research.md`. If the origin doesn't carry the tool name on 2.1.312, recover it from the row's `tool_use_id` against the preceding `tool.call` (kept in `$.state` by a second hook) before building further.
2. Add `skipIn: ["result"]` and regenerate the data twin; the consistency check and the existing `test_scripts.py` cases stay green; add the two additive cases.
3. `secret-mask.ts`: `'result'` in `Scope`, the `LOOKS.result` entry, `warning()`; tests for wording and for holding no value.
4. `output-warning.test.ts` for the pure parts, then `output-warning.ts`: redact-list rule, 256 KiB limit, rate rule, the content rewrite.
5. The `session.append` hook in `register.tsx` with the `.catch` (fail open plus loud toast); hook tests on each kind and each tool class.
6. `userConfig` (R4: the string option, else two booleans), README mods table and `docs/site` through `skill-docs`; mark the spec Implemented.

## Risks

- **API churn** (early access): the row's origin and content shape on the pin (R1); whether `userConfig` takes a string (R4).
- **Placeholder written back**: why `Read`/`Grep` are not redacted by default; a person who adds `Read` to the list accepts it (documented).
- **False comfort**: redaction after the tool ran isn't recall; the toast says "treat as exposed" and never "erased".
- **False positives** in `Bash` output (fixtures, docs): high-confidence kinds only, a rate limit, per-tool and global off switches.
- **Self-exposure**: a test that printed a mismatch would print the fixture; fixtures are fake by construction and the no-value test guards the outputs.
- **A failing hook**: fail open by design; a row is never dropped.
